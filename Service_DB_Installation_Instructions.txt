/*************************************
 *									 *
 *			How to Create a 		 *
 *		New MySQL Server Instance    *
 *		  and Windows Service	 	 *
 *									 *
 *************************************/

 What you will need:
	-MySQL Workbench or other SQL editor.	(For this example we are using MySQL Workbench version 8.0)
	-Powershell
	-Administrator Rights


Overview: 
	For this example we will be utilizing multiple microservices. To properly demonstrate this we will need these services to be operational at the same time.
	Although you could use a single DB connection with multiple schemas most modern microservices may not be owned or operated by a single entity, for that reason we are 
	demonstrating how multiple services working in parallel with one another can be utilized while operating across different ports simulating the microservices operating across
	the web or in different systems.

	To this end we are going to show you how to create and run a new MySQL DB Service using a port we are specifying.

	NOTE: 	It is always important to verify port availability and functionality across applications that are running on your server/system to ensure that there is no overlap and you are
			referencing the correct port.

			Because MySQL by default uses Port 3306 we will be specifying that our new service is operating on the unused port 3401.

			For this example we will be creating the "UserService".

Steps: 
	1) Confirm that no application or service on the system is currently listening on desired port.
		- Open Powershell as Administrator
		- Run Command: "Get-NetTCPConnection -LocalPort {your desired port number} -ErrorAction SilentlyContinue"
			- Receiving no result is a good indication that there is nothing currently listening on that port.
			- Ex: Get-NetTCPConnection -LocalPort 3401 -ErrorAction SilentlyContinue
		- You can also google search your port number but that is less accurate.
		- Confirmed there is no built-in service that utilizes port 3401.

	2) Locate Pathname for MySQL Directory Program Data and the my.ini file
		- If freshly installed to the C: drive the Location should be "C:\ProgramData\MySQL\MySQL Server 8.0\my.ini"
		- Open Powershell as Administrator
		- Run Command:
			- Get-CimInstance Win32_Service |
				Where-Object {$_.Name -like "*MySQL*"} |
				Select-Object Name, State, PathName

	3) Create the Directories we will need for our new Service
		- Open Powershell as Administrator.
		- Create a new UserService Directory for MySQL ProgramData
			- Run the Command: "New-Item -ItemType Directory -Path "{MySQL ProgramData Path}\{Desired ServiceName}" 
			- Example: New-Item -ItemType Directory -Path "C:\ProgramData\MySQL\UserService"
		- Create a new Data Directory for the Service Data
			- Run the Command: "New-Item -ItemType Directory -Path "{MySQL ProgramData Path}\{Desired ServiceName}\Data" 
			- Example: New-Item -ItemType Directory -Path "C:\ProgramData\MySQL\UserService\Data"

	4) Create the my.ini file for the new Service.
		NOTE: This is important (Each Service requires its own .ini file so that the different service configurations can be setup)
		- Open Powershell as Administrator
		- Run command to create the new my.ini file
			NOTE: This should not be made in your Data Directory but instead in the Service Directory.
			- Example: New-Item -ItemType File -Path "C:\ProgramData\MySQL\UserService\my.ini"

	5) Update the my.ini file with the configuration you need for your service
		- Open Powershell as administrator and navigate to your service directory
		- Open the my.ini file
			- run command "my.ini" from the directory it launches the file in notepad
		- Update the file and save the configuration
			- you need to provide the following:
				[mysqld]
				- port number: the port number you want the service to run on.
				- basedir: the directory that the MySQL Server runs on from the Program Files. 							ex: "C:/Program Files/MySQL/MySQL Server 8.0"
				- datadir: the data directory where the schema and service information will be saved/retrieved from. (Made in step 3)
				- server-id: the id this server is registered as. NOTE: The Server-Id uniquely identifies this MySQL instance when features such as replication are used. Give each locally running instance a unique value.
				[client]
				- port number: Defines the default port MySQL client programs will use when connecting with this configuration.
			- Use the MySQL ProgramData/Data directory created in step 3,
			-Example:
				[mysqld]

				port=3401

				basedir="C:/Program Files/MySQL/MySQL Server 8.0"
				datadir="C:/ProgramData/MySQL/UserService/Data"

				server-id=2

				[client]

				port=3401


	------- IMPORTANT ---------
	-- Before initializing the instance, verify that datadir and the new my.ini file points to the new service's Data directory.	--
	-- Never point multiple MySQL instances at the same data directory.																--
	-------------------------


	6) Initialize the new Service MySQL data Directory
		- Open Powershell as Administrator
		- Run Command for the mysqld.exe application to use the newly create my.ini file as its default and initialize the new service.
			-Example:
				& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqld.exe" `
				  --defaults-file="C:\ProgramData\MySQL\UserService\my.ini" `
				  --initialize `
				  --console
		NOTE: once completed a temporary password will be created, save this password as we will need it to login to the new service for the first time later.

	7) Install the new Service to the current Server/Computer
		- Open Powershell as Administrator
		- Run Command that will install the new service including my.ini file as the default configuration.
			-Example:
				& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqld.exe" `
				  --install MySQL_UserService `
				  --defaults-file="C:\ProgramData\MySQL\UserService\my.ini"

	8) Start the new Service
		- Open Powershell as Administrator
		- Run the command to start the new Service
			- "Start-Service {your service name}
			- Ex: Start-Service MySQL_UserService

	9) Verify the Service is now up and running.
		- Open Powershell as Administrator
		- Run Command Get-Service *mysql*
			NOTE: If you already had the default MySQL Service created it should show 2 services and their status otherwise it will show just the new service with the Header Running
			- Ex: Running  MySQL_UserService

	10) Verify Ports are working correctly
		- Open Powershell as Administrator
		- Run Command: "Test-NetConnection {your connection IP} -Port {your specified Port}"
			-Ex: Test-NetConnection 127.0.0.1 -Port 3401
		NOTE: you want to see something akin to TcpTestSucceeded: True

	11) Create new MySQL Workbench Connection for the new service
		- Open MySQL Workbench
		- Click the (+) on Create new Connections
		- Fill out the IP Address for localhost (127.0.0.1) and Port Number information used. NOTE: This can be adjusted later using the Workbench configuration and .ini files.
		- Specify root as the username for first login. NOTE: You can change this later as necessary but you neet to access it for the first time as the root to prompt the password change.
		- It will ask you to change the Password, use the password autogenerated in step 6 and enter your new connection PW.
		- Save the new connection PW.
		- For Application use, create a dedicated MySQL User with only the permissions required by the service rather than configuring the application to connect as root.
			- Examples of these Users are as follows:
				- NOTE: You do not need all of these users for every DB just the bare minimum required to get the functionality desired to work correctly.
				- Create Read_User			(User Permissions that are allowed to only read data from the DB.	ALLOWS ACCESS TO: (SELECT))
				- Create Write_User			(User Permissions that are allowed to only write data to the DB.	ALLOWS ACCESS TO: (INSERT, UPDATE, DELETE))
				- Create ReadWrite_User		(User Permissions that allow the user to read and write to the DB.	ALLOWS ACCESS TO: (SELECT, INSERT, UPDATE, DELETE))
				- Create Admin_User			(User Permissions that allow the user to alter the Schema.			ALLOWS ACCESS TO: (CREATE, DROP, ALTER))

	12) COMPLETE!

	You are now ready to create and manipulate the Schema for your new Service!

	Now we just have to do this 2 more times for our other services, hooray!
